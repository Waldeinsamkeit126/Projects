# Kaggriculture 闭环评测流程

## 为什么替换旧流程

`replay_evaluate.py` 会把在线对手的历史动作开环重放。候选策略改变局面后，
后续历史动作可能失效，因此该结果只能用于复现附近行为，不能作为版本晋级依据。

`benchmark_matrix.py` 会让两个代理实时决策，并固定以下条件：

- 每个代理对同时交换两个座位；
- 开发种子和留出种子互斥；
- 报告保存代理源码路径和 SHA-256；
- 同时统计胜分率、分差、收入、座位表现和按种子分块的置信区间。

## 当前基线结论

- V2 明显弱于后续版本，历史 Kaggle 分数不能直接代表当前闭环强度。
- V8、V9、V10 在基线矩阵中结果完全相同，新增条件没有覆盖常见基线局面。
- 后续版本存在明显座位差异；0 号位远强于 1 号位。
- V12 座位混合候选在中间验证上提升，但在最终未见种子 2000--2007 上与
  V10 同为 46 胜、34 负，因此不满足提交门槛。

## 晋级门槛

候选必须依次满足：

1. 开发集对固定对手池的胜分率不低于当前版本；
2. 中间验证集同时提高胜分率和平均分差；
3. 最终未见种子只运行一次，胜分率必须高于当前版本；
4. 所有对局状态为 `DONE`，单步动作时间不越界。

当前保留 V10，不提交 V12。下一轮应针对 1 号位建立可泛化的早期市场状态选择器，
并为最终测试换用全新的种子区间。
