## 保存和使用

### Codex 联网账户要求

本机实际观察到：默认命令运行于 `CodexSandboxOffline`，批准联网后改为 `CodexSandboxOnline`。这两个账户不能互相解密 DPAPI CurrentUser 密文；这里的“当前账户”指命令执行账户，并非桌面登录账户。

因此必须先取得本轮联网权限、确认执行账户为 `CodexSandboxOnline`，再保存或读取供模型调用使用的凭证。后续轮次也先开启经批准的联网访问，再启动 `run.ps1`。保存入口会在 Offline 账户下拒绝操作，且不会读取剪贴板。权限错误会终止状态检查，不会被当作“没有保存”。不通过放宽 ACL、改用 LocalMachine 加密或修改 Codex 沙箱设置来绕过隔离。

旧 Offline 密文保留时使用工作区 `.private-offline-backup`，该备份也必须排除于 Git、ZIP 和同步分享之外。它仍只供原执行账户解密，不能直接复制回来供 Online 使用。只有在 Online 下保存并在另一个 Online 命令进程中验证成功后，才可认定自动读取配置完成。

密文位置：工作区 `.private/tianchi-bailian.dpapi`。该目录已加入根目录 `.gitignore`，不在比赛提交输出目录内。密钥及其指定的阿里云端点一起通过 Windows DPAPI CurrentUser 加密；目录和文件设置为当前 Windows 账户独占 ACL。保存时会回读验证，已有凭证不会被覆盖。

`credential-store.psm1` 是存储模块，`credentials.ps1` 是管理入口。它们的源码不含密钥。保存命令只从本机当前剪贴板接收密钥，终端输出只含保存/校验状态，不含原文。成功后仅在当前剪贴板仍是同一密钥时清空它；不会删除剪贴板历史或其他新复制的内容。

```powershell
# 查看是否已有文件，不输出密文或密钥。
.\credentials.ps1 -Action Status

# 只验证解密和 ACL，不调用 API。
.\credentials.ps1 -Action Test

# 仅在明确授权首次保存且已经复制密钥时使用。
# BaseUrl 必须是与该密钥匹配的阿里云端点，不能是代理或其他服务。
.\credentials.ps1 -Action Save -BaseUrl 'https://你的业务空间.cn-beijing.maas.aliyuncs.com/compatible-mode/v1'
```

后续使用 `run.ps1` 启动比赛程序。只有显式 `--allow-paid` 且没有 `--dry-run`、当前进程又未配置 `DASHSCOPE_API_KEY` 时，启动器才加载本机密文。它仅临时设置本次进程的环境变量，子进程结束后在 `finally` 中恢复；不写用户级或系统级环境变量。

已经显式设置的进程凭证优先。仅在没有显式 BaseUrl 或 WorkspaceId 时采用密文绑定的端点，避免静默覆盖调用者的配置。`run.mjs` 仍会检查模型和端点范围。直接使用 `node run.mjs` 不会自动加载此存储。

保存密钥不等于授权无限计费。仍须遵守每轮约定的请求次数、token 上限和用途；不会自动提交比赛。2026-09-17 完成的 B 组上限为 6 次，实际使用 4 次，未重跑 A 组；该轮额度不自动转为其他实验授权。

## 安全边界

- 密文通常只能由本机相同 Windows 账户解密。换机器、重装系统、删除用户配置等可能使其失效，届时应从百炼重新配置或创建新密钥。
- 同账户恶意程序或获得足够权限的攻击者仍可能读取运行中的明文；DPAPI 不能保证零泄露，也不能防住已被控制的账户。
- 运行 API 客户端必须短暂解密。脚本会清空可变明文字节、释放 SecureString/非托管缓冲区并恢复环境变量，但不能保证托管运行时的每份字符串副本立即从内存抹除。
- `.gitignore` 不会阻止手动 ZIP 全工作区、强制 Git 添加、其他同步/备份工具。分享或打包时必须排除 `.private` 和 `.private-offline-backup`；ACL 也不是对管理员绝对保密的保证。
- 清空当前剪贴板不等于清除 Windows 剪贴板历史、云同步副本或之前发出的聊天消息。以前泄露过的密钥仍需在百炼撤销，不能靠本次加密补救。
- 更新/删除本地凭证须明确授权；当前 Save 拒绝覆盖已有文件。删除本地密文不会撤销云端 API Key。
